# Security tests

Security tests analyze your extension’s codebase for potential vulnerabilities, security risks, and best-practice violations. By examining your code with a series of automated scanners and static analysis tools, these tests help you identify and fix issues before they can harm merchants or customers.

## What tools are used?

The Security test leverages multiple tools, including:
- PHPCS: Checks for adherence to WordPress and WooCommerce security standards.
- SemGrep: Runs rules to detect insecure patterns and common vulnerabilities.
- Composer Audit: Identifies known vulnerabilities in third-party packages.
- WPScan: Compares your extension against a database of known WordPress plugin vulnerabilities.

These tools work together to provide comprehensive coverage of potential issues, from code-level risks to outdated dependencies.

## Test outcomes

- **Success:** No security issues, errors, or warnings detected.
- **Warning:** Potentially risky or deprecated functions identified, but no critical vulnerabilities found.
- **Failed:** One or more serious vulnerabilities or security errors detected, requiring immediate attention.

## How to interpret results

If the test returns warnings or fails:
- Check the logs or generated report for details on the flagged issues.
- Determine if these are false positives or genuine security concerns.
- Address legitimate vulnerabilities by updating code, dependencies, or configurations.

If you identify false positives, consider adding inline comments to suppress unnecessary warnings or reaching out for assistance if a rule seems incorrect.

## AI-Assisted recommendations

If the test identifies issues, you can request AI-assisted recommendations to guide you on potential fixes. Keep in mind that these suggestions may require review and adaptation, as they are generated by a model trained on common insecure and secure code patterns.

## Handling false positives

False positives can sometimes occur. If you’re confident an issue is not a real risk:
- Temporarily suppress the warning using a PHPCS or SemGrep ignore comment.
- Contact QIT support if the false positive recurs or you believe the rule should be improved.

## Best practices

- Regularly run security tests, especially before releases.
- Keep dependencies and frameworks updated.
- Follow secure coding standards and guidelines to reduce the likelihood of warnings or failures.
